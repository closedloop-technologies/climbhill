Repo-local self-improvement

Controlled loops for coding agents.

ClimbHill.ai helps agents improve a Git repository through bounded Runs and Attempts, policy gates, durable experiment memory, evaluation, reports, and human promotion paths.

What ClimbHill provides

A substrate for repeated improvement attempts, not a one-off agent.

The project defines repository support files, a Codex plugin, an MCP server, skills, resources, registry, policy checks, evaluation records, and reporting needed for safe recursive improvement.

Policy gates

Protect tests, evals, workflows, lockfiles, migrations, infra, and security-sensitive code by default.

Experiment memory

Record every Attempt, patch, branch, commit, Evaluation, cost, failure, and human Decision.

Attempt evolution

Compare parallel attempts, sample historical failures, recombine promising ideas, and track lineage.

Reviewable reports

Generate concise reports with objective, baseline, policy, Attempts, Evaluations, costs, risks, and next actions.

Core loop

Agents climb by preserving what every attempt teaches.

ClimbHill starts when a repo needs controlled optimization and ends when Attempts are evaluated, recorded, reported, and promoted into a PR-ready branch, issue, plan, or next loop.

1

Align the repository

Create goal, architecture, testing, eval, resource, skill, and policy files without overwriting existing guidance.

2

Run bounded Attempts

Use CLI or MCP tools to create Runs, register Attempts, attach patches, enforce policy, and record Evaluations.

3

Compare and decide

Recommend the strongest Attempt, record human Decisions, and preserve rejected Attempts as future evidence.

4

Reflect into issues

Analyze the experiment tree to propose missing docs, weak tests, stricter policies, better skills, and next runs.

Make improvement attempts auditable, comparable, and reusable.

The MVP is local-first: Codex plugin, MCP server, SQLite registry, files, Git, Markdown reports, conservative policies, and human-controlled promotion.
