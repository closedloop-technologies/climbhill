# HarnessEval-W

## Why this matters to ClimbHill

HarnessEval-W suggests that an Evaluation should be an inspectable evidence structure rather than only a scalar score.

## What the paper establishes

HarnessEval-W decomposes an evaluation question into narrower subproblems, assigns specialized agents to gather evidence with relevant tools and context, and then has a parent evaluator validate and synthesize that evidence into a verdict. The result is a transparent evidence tree whose intermediate observations and reasoning can be inspected instead of a benchmark returning only a number. The work is aimed at visual world models, but the architectural pattern is broader: evaluation can itself be agentic while still preserving provenance and a reviewable chain from observations to claims.

## ClimbHill design consequences

- Evaluation artifacts should preserve claims, observations, checks, conflicts, and evidence references.
- Scalar metrics can summarize evidence but should not replace it.
- Continuation Analysis should reason over frozen Evaluation evidence rather than invent new facts.
- Parent/child evaluation structure can support specialist checks while keeping one final Evaluation artifact.
- Contradictory evidence should remain visible rather than being silently averaged away.

## Design question

Should ClimbHill formalize an evidence graph inside Evaluation artifacts, or keep the schema minimal and define an extensible evidence-reference convention that richer evaluators can populate?
