# Skill2Query

## Why this matters to ClimbHill

Skill2Query becomes relevant once ClimbHill has enough evaluators, diagnostic procedures, research adapters, and improvement skills that selecting the right machinery is itself a retrieval problem.

## What the paper establishes

Skill2Query parses skill documents into structured representations of capabilities, parameters, and examples, then generates pseudo-queries that resemble realistic requests for those skills. Those generated queries can augment retrieval indexes, expand incoming queries, or provide training data for retrievers. The reported experiments show that structure-aware pseudo-query generation improves retrieval across sparse, dense, and routing settings and that better retrieval can improve downstream agent task success. The useful architectural point is that a skill's internal structure provides stronger retrieval supervision than treating the entire skill document as one undifferentiated text blob.

## ClimbHill design consequences

- Keep skill capability, applicability conditions, parameters, evidence requirements, and examples explicit enough to index separately.
- Generate synthetic invocation cases when evaluating skill retrieval.
- Evaluate retrieval on whether the selected skill can actually resolve the uncertainty, not only semantic similarity.
- Treat routing quality as an evaluable Learning Focus once the skill library grows.

## Design question

At what library size or routing error rate should ClimbHill graduate from simple metadata/embedding retrieval to a benchmarked skill-retrieval subsystem with generated query coverage?
