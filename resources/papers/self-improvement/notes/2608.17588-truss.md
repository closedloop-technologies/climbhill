# TRUSS

## Why this matters to ClimbHill

TRUSS is a concrete promotion pipeline for proposed changes to reusable agent machinery: inspect them, execute them in shadow, capture traces, repair failures, validate again, and only then admit them.

## What the paper establishes

TRUSS generates and repairs Agent Skills using both static evidence and controlled execution. Candidate skills first pass checks over their claims and safety properties. Accepted candidates are then loaded into a shadow agent inside a brokered execution environment where requested actions are policy-checked and recorded as provenance-preserving traces. Functional failures and safety violations are linked back to the responsible skill content and feed another repair cycle. This demonstrates why inspecting a candidate artifact or looking only at final task success is insufficient: behavior and side effects must be observed during execution.

## ClimbHill design consequences

A durable candidate improvement should be able to pass through:

`propose → inspect → shadow execute → evaluate effects → repair → validate → promote`

Apply the pattern not only to skills, but also prompts, tools, evaluators, continuation policies, and other Learning/Alignment Focus artifacts.

## Design question

Can ClimbHill represent shadow execution as an ordinary Attempt with a stricter Authorization Envelope, or does promotion validation need a first-class execution mode distinct from optimization Attempts?
