# CompoSkill

## Why this matters to ClimbHill

CompoSkill shows that individually acceptable skills can become unsafe when composed. Validation is therefore a property of an action path as well as of each node on that path.

## What the paper establishes

The paper studies skill-chain attacks in which every individual marketplace skill can pass an isolated scanner while the combined workflow creates a risky capability or side-effect chain. It models composition through a graph of skills and demonstrates that dangerous behavior can emerge from outputs, permissions, or side effects that bridge otherwise acceptable components. This exposes a structural gap in per-skill certification: local safety does not imply path-level safety.

## ClimbHill design consequences

- Do not treat individually validated tools, skills, or actions as automatically safe in arbitrary combinations.
- Validate the candidate action path under the actual Authorization Envelope before execution or promotion.
- Model dataflow and side-effect edges, not only declared dependencies.
- Re-evaluate path safety when a new skill changes reachable compositions.
- Promotion tests should include representative compositions, not only isolated skill tasks.

## Design question

Can ClimbHill derive a bounded composition graph from a Continuation Analysis recommendation and deterministically check that the proposed path introduces no unauthorized capability bridge before execution begins?
