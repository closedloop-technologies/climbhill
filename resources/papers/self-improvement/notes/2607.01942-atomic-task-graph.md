# Atomic Task Graph

## Why this matters to ClimbHill

Atomic Task Graph provides a useful model for preserving validated work while repairing only the region invalidated by a failure.

## What the paper establishes

ATG represents agent work as an explicit directed acyclic graph rather than an implicit textual trajectory. High-level nodes are recursively compiled into executable subtasks while preserving their input/output interfaces. Execution respects dependency order and can parallelize independent branches. When a failure occurs, the framework uses graph history to localize the affected region, freezes unaffected validated nodes, and repairs only the necessary subgraph. This creates a cleaner separation between verified intermediate results and the region currently being reconsidered.

## ClimbHill design consequences

- Preserve validated evidence and artifacts unless new evidence invalidates an assumption they depend on.
- Prefer localized repair to rewriting a whole plan or Run after one failure.
- Make dependencies between produced artifacts and downstream evaluations explicit enough to calculate the affected region.
- Treat graph history as evidence for why a particular region was reopened.
- Keep interface contracts stable when refining an internal implementation.

## Design question
